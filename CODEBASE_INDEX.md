# Codebase Index

Last reviewed: 2026-05-12

Purpose: a compact map for surgical codebase reads. Keep this file current when module ownership, commands, or architecture changes.

## Stack

- Strict TypeScript Vite browser app using native ES modules plus a module Web Worker for chunk CPU work.
- Three.js handles rendering, camera, materials, lights, and meshes.
- Rapier (`@dimforge/rapier3d-compat`) handles active rigid-body cuboid-envelope debris inside the player bubble through the local `src/rigidDebris.ts` adapter.
- World units are metric: `1 block = 1 meter`, defined by `METERS_PER_BLOCK` in `src/voxelConstants.ts`.
- The app code owns chunks, terrain generation, voxel meshing, partial-block terrain carving, player movement, collision, ray picking, held-item action routing, HUD, minimap, admin/test-lab tooling, impact damage, parked crater/scar visuals, debris lifetime/bake-out, rubble cover proxies, projectile physics toys/cores, and hitscan cores.

## Runtime Flow

1. `index.html` loads `src/main.ts`.
2. `main.ts` creates the Three.js renderer, scene, lights, camera-following generated skybox, `VoxelWorld`, `PlayerController`, and small UI helpers for quality, debug HUD, minimap, and world list rendering.
3. `main.ts` opens the async IndexedDB save registry, then starts on the home screen; `worldMenu.ts` renders saved-world rows, and loading, creating, Superflat Lab creation, or confirmed deletion updates the saved-world slots, active seed, and optional player resume location.
4. `VoxelWorld` reads the saved chunk key index when a world loads, but chunk payloads stay lazy and stream from IndexedDB only when needed.
5. `VoxelWorld.ensureChunksAround` creates initial spawn chunks after a world is loaded; generated chunks use seeded `fbm2` terrain noise from `src/terrain.ts`.
6. During play, `main.ts` passes the camera view direction and camera frustum into `VoxelWorld.streamChunksAround`; cached chunk-radius offsets populate the queue only when the player crosses a chunk boundary or the load radius changes, unchanged unload windows skip loaded-chunk sweeps, then chunk generation queues are picked as a bounded slice that keeps nearby chunks first and prioritizes chunks inside the camera view.
7. Completed worker/storage chunk results are also applied in camera-prioritized bounded slices, so high-distance fresh worlds do not upload large bursts of chunks or let offscreen results steal the visible-frame budget.
8. Dirty chunks are tracked by key, then use the same bounded frustum-biased priority before meshing in the worker as typed-array buffers and uploading through `Chunk.applyMeshData`; worker and fallback meshes both use `src/blockColors.ts` so deterministic tint buckets do not change between mesh paths.
9. If workers are unavailable or fail, `VoxelWorld` falls back to synchronous chunk generation and `Chunk.rebuildMesh`.
10. Each visible animation frame updates player motion, optional F8 test-avatar scripting, Nova Pilot companion motion/reactions, Nova Terminal runtime context, chunk streaming, physics toys/cores with reusable impact buffers and slider-tuned projectile launch size/velocity, partial-block terrain carving, rubble-core collision, damage health-bar projection, Rapier rigid debris and temporary static terrain/rubble colliders, settling-region debris finalization, orphan settled-fragment fallback absorption, rubble patch merge/support/fall/terrain-promotion rules, a sleep-aware split core/debris broadphase shove pass, speed-gated impact damage, quality-scaled and slider-tuned physics body budgets, instanced debris render batches, dirty mesh scheduling, partial-block mesh refreshes, HUD/debug text, minimap, and final render only while a world is active. Hidden tabs and long resume gaps skip expensive work and reset profiler/minimap meters; once chunk, worker, save, debris, and awake-physics work has drained, visible worlds with no input for five minutes stop RAF entirely and use a low-frequency idle heartbeat until focus, visibility, pointer, or keyboard activity resumes the loop. The debug HUD receives smoothed CPU timing buckets for player, chunk, physics, mesh, minimap, render, miscellaneous work, settling-region pressure, rigid debris body/collider pressure, fragment instancing pressure, and rubble cover pressure.
11. `Exit to Home` saves the player feet position plus look angles, flushes async chunk writes, and unloads the active world view; switching worlds happens from the home screen, not the pause menu.
12. The scroll wheel selects the current held item stack from the hotbar. `src/items.ts` owns reusable item definitions and primary/secondary action descriptors, while `src/hotbar.ts` only owns selection and action lookup. The current item set is Unarmed, placeable blocks, Physics Core, and Hitscan Core: Unarmed is intentionally inert, selected blocks use left click to break and right click to place, selected Physics Core uses left click to throw, selected Hitscan Core uses left click to fire an instant smallest/fastest core trace, and right click stays reserved for both core weapons.
13. Block edits go through `voxelRaycast` plus `VoxelWorld.setBlock`; edited chunk snapshots are coalesced per chunk before IndexedDB receives raw binary chunk payloads, and neighboring chunks are marked dirty when edge blocks change.
14. Projectile and hitscan cores resolve terrain impacts through the same carving path. Projectile impacts above 2 m/s carry the source core, incoming velocity, and core radius after the swept core moves; Hitscan Core fires a fixed smallest/fastest trace from the camera and applies the same impact payload immediately. Both call `VoxelWorld.carveBlock` with `PARTIAL_BLOCK_CORE_DAMAGE` (`1`) against 10-HP ordinary terrain. A chipped terrain block stays solid for player/debris collision, raycast, and health tracking, but core collision asks `VoxelWorld.canProjectileHitBlock` to test the segment against only the remaining bite-lattice material. Normal chunk meshing treats chipped cells as custom geometry through partial-block masks while `PartialBlockMeshField` renders an apple-bite style partial volume from a hidden 3x3x3 visual lattice. Lattice cells are removed in proportion to damage/maxHealth, ranked by distance from the swept core trajectory and then by depth, and persisted once removed, so HP/material loss and visible fill stay coupled without letting later hits visually refill earlier bites or making the old 27-piece grid gameplay truth again. Tiny fast cores can continue through a complete three-depth bite tunnel when their exit cell is air; projectile cores get an exit pose through `PhysicsToy.continueAfterPierce`, while Hitscan Core advances its ray origin and reduced impact speed through the same tunnel continuation. Existing visual tunnels are core-open too: later tiny shots ignore the removed cells and can hit a visible block behind the chipped voxel, while shots through remaining side material still collide with the chipped block. Every carve ejects only the rubble-material slice it removed as a capped chip burst, and once accumulated carve damage exhausts block health the voxel is removed, the leftover material spawns as proportional loose shaped fragments, and the custom bite mesh is cleared so the final break leaves air instead of a wrinkled surface puddle. Visible fragment count is only a performance/rendering knob: one full block is `1.0` normalized material volume distributed over its chip and final-fracture events for cover shape, support, and dense-pile promotion, while rubble HP is scaled separately to one generated `Rubble` block's durability per full block of material. New fractures join nearby temporary settling regions, burst apart for a short breakup grace, then briefly collide/glue/stack/clump with same-region debris, add exaggerated shard tumble through `PhysicsToy.angularVelocity`, and rest on terrain or existing partial-height rubble surfaces. Debris reports whether it touched support during its most recent physics update and whether its sleep state is support-anchored, allowing supported glue-connected clumps to sleep even when upper shards are resting on other debris rather than terrain. Sleep checks run per glue-connected component and then per-fragment support chain so a grounded shard can support stack-like upper debris without freezing side-linked or visibly floating debris. Glue links also maintain a minimum readable center separation so the sticky clump illusion does not preserve obvious fragment interpenetration. In the browser loop those owned regions now stay active or sleeping while inside the quality-scaled player debris bubble; they finalize into rubble only when the player leaves the radius plus buffer, physics-budget pressure needs relief, or full cleanup clears the world. Budget pressure finalizes farthest regions first, then absorbs far/outside orphan fragments, and only prunes old cores directly as a last resort so fragment material is not deleted. Rubble patches merge across neighboring same-height cells up to a bounded patch size, skip internal mesh faces so they read as connected debris, keep bounded surface samples from settled fragments, render a faceted low-poly heightfield draped over those samples, bake capped static shard samples into the same mesh for silhouette and future re-break data, keep sparse material in local sample footprints instead of full-cell tiles, share edge heights across neighboring broad piles, rise subtly toward adjacent solid terrain, and expose partial-height support queries so the player can stand on larger piles without making every pile a full terrain voxel. Rubble checks support each active frame: unsupported cells fall one voxel cell, falling cells merge into piles below, and dense supported cells compact into the generated solid `Rubble` block only after more than one full block-volume of debris accumulates. Active projectile cores can still shove loose fragments and collide with rubble patches without enabling permanent debris-debris pair generation; `PHYSICS_CORE_BLOCK_DAMAGE` (`30`) still applies to directly struck rubble piles, only immediate neighbors get a small non-lethal chip if that pile breaks, and a projectile core is consumed if it destroys the pile cell it struck. `X` removes only thrown cores so rubble experiments can stay in place, while the settings-panel `Despawn All Objects` button clears cores, loose debris, settling regions, rubble, and damage indicators. Projectile cores also sleep after settling so old shots do not keep paying per-frame voxel collision cost forever.
15. `Enter`, `F9`, or the pause-menu `Nova Terminal` button opens the local terminal pane. Normal text feeds replies from the `NovaContextJournal`; slash commands and bare known admin commands route through `src/adminCommands.ts`. Opening the terminal suspends movement/look without showing the pause menu and resumes pointer lock when closed. The conversational implementation is local context-aware text only; a real model/proxy hook is future work.
16. Dev reloads and browser unloads run `disposeRuntime()` from `src/main.ts`: the active animation frame is canceled, main event listeners are aborted, player input listeners are disposed, active chunks/worker/physics/Nova helpers are released, and the renderer forces WebGL context loss so Firefox's GPU process does not keep old dev contexts around.

## Base And Bolt-On Boundaries

Long-term direction: keep this repo as the kitchen-sink proving ground, but shape mature systems so a new game instance can pick a base plus selected bolt-ons without dragging every experiment along. The immediate goal is documentation and small interface boundaries, not a package split.

- Base voxel instance: `index.html`, `src/main.ts`, `src/world.ts`, `src/chunk.ts`, `src/chunkWorker.ts`, `src/chunkProtocol.ts`, `src/terrain.ts`, `src/voxelConstants.ts`, `src/collision.ts`, `src/raycast.ts`, `src/blocks.ts`, `src/blockColors.ts`, `src/voxelLighting.ts`, `src/lighting.ts`, `src/skybox.ts`, and `src/shadows.ts`. This is the hardest piece to extract because chunk storage, meshing, terrain generation, collision queries, and the play loop are intentionally interwoven for now.
- Player-control bolt-on: `src/player.ts`, `src/playerMovement.ts`, `src/playerSpeed.ts`, and `src/sprintFeedback.ts`. Desired extraction contract is a world collision/support query, a camera/input surface, and a movement-tuning object.
- Save/world-menu bolt-on: `src/chunkStorage.ts`, `src/worldMenu.ts`, `src/deleteWorldDialog.ts`, plus the home-screen orchestration in `src/main.ts`. Desired extraction contract is an app identity/storage namespace, seed metadata, edited-chunk payload format, and optional player resume pose.
- Held-item/action bolt-on: `src/items.ts`, `src/hotbar.ts`, plus focused action dispatch in `src/main.ts`. This is already close to portable because held-item behavior is mostly data plus a small runtime dispatcher.
- Damage/targeting feedback bolt-on: `src/targetHighlighter.ts`, `src/damageIndicators.ts`, terrain/rubble damage events in `src/engineEvents.ts`, and the target-selection hooks in `src/main.ts`. Desired extraction contract is a targetable cell/source id, world-to-screen projection, and a health-event payload.
- Partial-terrain carving bolt-on: `src/partialBlocks.ts`, carve ownership in `src/world.ts`, partial render masks in `src/chunkProtocol.ts`/`src/chunkWorker.ts`, normal-cube suppression in `src/chunk.ts`, and `handlePhysicsImpact`/`PartialBlockMeshField` wiring in `src/main.ts`. Chipped terrain remains a full voxel through `VoxelWorld.isSolid`, while its visible custom mesh removes hidden lattice cells in proportion to damage and ranks those cells by core trajectory/radius. Tiny-core piercing is projectile-only and returns an exit pose through the carve result; later core projectile collision can also pass through already-removed lattice cells via `VoxelWorld.canProjectileHitBlock`. Final fracture clears the bite mesh and leaves air. Save persistence and richer non-cuboid collision are future deliberate steps.
- Impact-scar prototype: `src/impactCraterField.ts` is parked after the decal-like crater experiment. Keep it visual-only if reused later; it should not own terrain damage, rubble material, collision, or the active core impact route.
- Quality/performance bolt-on: `src/qualityPresets.ts`, `src/qualitySettings.ts`, `src/qualityController.ts`, `src/physicsBudget.ts`, `src/physicsCoreSettings.ts`, `src/rigidDebrisBudget.ts`, `src/frameTimings.ts`, and debug-HUD display in `src/debugHud.ts`. This should stay policy-driven: presets tune budgets/radii/counts, while features ask for budgets/settings instead of hard-coding their own limits.
- Physics-core bolt-on: `src/physics.ts`, `src/hitscanCore.ts`, `src/physicsCoreSettings.ts`, plus selected core dispatch and `PhysicsToyCollider` use in `src/main.ts`. Desired extraction contract is scene ownership, collision bounds/support queries, impact callbacks, launch tuning for projectile cores, and fixed-envelope trace tuning for hitscan cores. Keep core behavior separable from debris and rubble so a new instance can keep projectiles or hitscan weapons without destruction cover.
- Debris-visual bolt-on: `src/blockFragments.ts`, `src/debrisShapes.ts`, and `src/physicsInstancing.ts`. This is one of the cleanest reusable pieces: given source material/block id, fragment positions, transforms, and shape metadata, it can render many transient fragments through shared geometries and instanced batches.
- Rigid-debris bolt-on: `src/rigidDebris.ts` plus budget policy in `src/rigidDebrisBudget.ts`. This is intentionally adapter-shaped: Rapier stays behind local methods, dynamic bodies use cheap cuboid envelopes, and terrain/rubble support enters through small path-lookahead static-collider refresh inputs.
- Rubble/cover bolt-on: `src/rubble.ts`, `src/debrisSettler.ts`, and `src/fragmentRubble.ts`. This is powerful but least portable today because it owns gameplay material accounting, support height, damage, raycast cells, fall/merge rules, and terrain-block promotion. Future extraction should split the durable cover proxy from the voxel-world promotion policy.
- Event/reaction bolt-on: `src/eventBus.ts`, `src/engineEvents.ts`, `src/novaPilotReactions.ts`, `src/novaContext.ts`, `src/novaChat.ts`, `src/novaChatPanel.ts`, and `src/novaPilot.ts`. Keep engine events generic enough that Nova can be removed, replaced, or kept as a flavor layer without rewriting damage, world, or physics systems.

When adding a new mature feature, add it to this list with three things: owning files, external contracts it should depend on, and the parts it should not directly own. Prefer small TypeScript interfaces at module boundaries once a second instance actually needs the system; until then, avoid premature package structure and keep the kitchen sink pleasant to work in.

- `VoxelWorld.savedChunkKeys` mirrors the persisted edited chunk index; `savedChunks` is only a cache of loaded edited chunk payloads.
- Saved worlds are local browser slots in IndexedDB; edited chunks persist as full binary chunk snapshots, which is simple and reliable but not a final save-file format.
- Player resume location is saved as feet position plus yaw/pitch in saved-world metadata; avoid storing raw camera height or crouch view offsets, or crouched exits can reload into terrain.
- Edited chunk saves are debounced and coalesced per chunk so rapid destruction does not spam IndexedDB with intermediate snapshots; call `VoxelWorld.flushStorageWrites()` before switching storage or unloading a world.
- Worker meshing has a synchronous fallback path; keep both paths healthy when changing chunk storage or mesh formats.
- Block tint variation is part of the greedy mesh key. Keep worker and fallback meshing on the shared `src/blockColors.ts` helpers so tint buckets stay deterministic and chunks do not repaint between mesh paths.
- Worker meshes treat missing neighbor chunks as temporarily solid so streaming does not draw chunk-edge walls before neighbors load and trigger a remesh.
- Chunk `revision` values invalidate worker mesh results for both local block edits and neighbor-driven dirty marks; do not let stale neighbor snapshots clear `dirty`.
- Large render-distance presets depend on bounded frustum-biased chunk and mesh selection in `src/world.ts`; avoid reintroducing full queue sorts, full chunk-radius queue refreshes, full unload sweeps, or all-loaded-chunk dirty scans on every frame. If code clears pending load state or makes a saved chunk fall back to generated terrain, call the queue-window invalidation path so unchanged-center streaming can safely repopulate missing work. If code loads or creates chunks directly, keep the unload-window and dirty/modified indexes in sync.

The panel is viewport-constrained and split into `Graphics` and `Gameplay` tabs to keep smaller windows reachable.
- Slider edits intentionally fork into the single `Custom` preset instead of mutating built-in presets; named custom preset management is future UI work.
- Browser worker behavior can differ from the build smoke test; reload the local app after worker pipeline changes and watch console logs/debug metrics.
- Firefox can retain WebGL/GPU-process memory across dev reloads if old contexts are not explicitly lost. Keep `disposeRuntime()` wired to `beforeunload` and Vite HMR, and keep long-lived Three.js helpers on a disposal path when adding new renderer-owned resources.
- Long idle sessions should hibernate instead of trusting browser RAF throttling. Keep `src/frameLoop.ts` and `VoxelWorld.hasPendingRuntimeWork()` in sync when adding new async queues or persistent simulation work, or the engine may sleep too early or run overnight again.
- `npm.cmd run test` bundles `tests/run.ts` into `.test-dist/` with esbuild before running in Node; `.test-dist/` is generated and ignored.
- `node_modules` and `dist` are generated and should not be scanned unless diagnosing dependency/build output.

- Object-object physics is split: Rapier owns active debris-debris cuboid contacts, while `PhysicsToyCollider` keeps the cheap core/core and core/debris shove pass in spatial hashes. Call both `PhysicsToyCollider.forget()` and `RigidDebrisSimulation.forget()` before disposing a toy so sleeping/static caches and Rapier bodies cannot keep stale references.
- Physics-core size and velocity sliders affect newly thrown player and Nova projectile cores only. Hitscan Core always uses the smallest core radius and highest configured impact speed. Core-vs-terrain contact uses a swept sphere path or hitscan trace so tiny fast cores hit the first remaining bite-lattice material along the segment; intentional piercing must happen only through `VoxelWorld.carveBlock` after the bite lattice opens a complete tunnel and confirms an air exit.
- Debris fragments are rendered through per-block/per-shape `THREE.InstancedMesh` batches in `src/physicsInstancing.ts`; Rapier writes active fragment transforms back into `PhysicsToy.mesh.position` and `mesh.quaternion`, while `debrisShape.visualScale` stays render-side and fragment meshes are not added to the scene individually.
- Partial-block terrain carving is in-memory first-pass terrain state. `VoxelWorld.carveBlock` keeps chipped cells solid for player/debris collision and raycast through `isSolid`, but `isRenderableSolid` makes chunk meshing skip those cube cells while `PartialBlockMeshField` draws the custom faceted bite volume. Thrown cores additionally ask `canProjectileHitBlock`, so projectile collision can pass through removed lattice cells while still hitting remaining visual material. Each carve result reports the normalized rubble-material volume it just ejected so `src/main.ts` can spawn chip debris without duplicating the final block budget, and may report a projectile-only pierce continuation when a small fast core opens a complete bite-lattice tunnel into air. Removed bite-lattice cells are stored on the partial block and only expand as damage increases, preventing later hits from visually refilling older bite marks when the rolling cut list changes. Bite ranking uses the incoming core line and radius: tiny cores favor one narrow column, larger cores favor a wider entry footprint. When a carved voxel breaks, `VoxelWorld` clears the custom bite mesh and leaves normal air instead of stamping the old wrinkled heightfield support puddle. Partial render masks must travel with worker mesh requests or the worker will resurrect full cubes over carved cells. Partial cells are not saved to IndexedDB yet; leaving the active world clears them.
- `ImpactCraterField` is now a parked visual-only prototype from the rejected decal-like crater pass. It should not be wired back into Physics Core terrain hits unless the feature is deliberately a surface scar again, and it must not become terrain collision, rubble material, or save data by accident.
- `Despawn All Objects` uses the full cleanup path and releases high-water instanced debris batches, while `X` removes only thrown physics cores and preserves fragment/rubble experiments.
- Rubble patches are the persistent gameplay representation of finalized debris. `RigidDebrisSimulation` owns active cuboid contacts inside the bubble, while `DebrisSettler` owns region grouping, material accounting, settled-rigid-body promotion, distance/budget bake-out, and legacy manual-fragment glue helpers for tests/fallbacks. Sleeping rigid-body regions bake into rubble even inside the player bubble, pressure relief finalizes sleeping regions before awake far debris, and old cores are pruned only as a last resort. Because the old sheet renderer is parked, forced pressure bake-out must preserve at least one static visual chunk per converted fragment or the material becomes invisible support-only rubble. `RubbleField` keeps sample-driven hidden support footprints, baked shard visual chunks for current pile silhouettes and future re-break data, cover raycasts, scaled health, core collision, walkable partial-height support queries, fall/merge behavior, and promotion into the generated `Rubble` block together; the old faceted/draped heightfield renderer is parked behind `RUBBLE_RENDER_DRAPED_SHEET_MESH` and should stay disabled unless that zoomed-out rubble mechanic returns deliberately. Do not reintroduce permanent per-shard gameplay collision when tuning cover behavior. Lower quality settings spawn fewer visible flying fragments, but fragment `rubbleMaterialUnits` preserves normalized block-volume material and low-quality regions expand carried material into multiple samples, so graphics quality does not change cover value; durability is scaled separately from visible shard count.
- The player and loose debris receive terrain collision and rubble support through the shared `CollisionWorld` contract in `src/collision.ts`; full voxel blocking still comes from `isSolid`, while partial-height surfaces should opt in through `getSupportHeight`.
- Engine/gameplay events are local typed pub/sub, not DOM events; keep cross-system reactions on `src/eventBus.ts`/`src/engineEvents.ts` instead of stringly `CustomEvent` wiring.
- Item actions are data contracts. Add future tools, weapons, consumables, or game-mode commands by extending `ItemAction`/`ItemDefinition` in `src/items.ts`, then dispatch the new action in `src/main.ts` or a focused gameplay owner; avoid reintroducing direct hotbar-kind checks.
- Nova Terminal chat is deliberately local-only for now. Do not put OpenAI/API credentials in browser code; use a tiny local/backend proxy when the real model hook happens.
- Pointer lock behavior is browser-sensitive; `requestPointerLock()` can return a promise or `void`, so keep the guarded catch path in `src/player.ts` and test movement changes in the browser, not just with `npm.cmd run build`.
- TypeScript migration helpers are historical prep tools now; source in `src` is expected to stay strict without `@ts-nocheck` or explicit `any`.
