# Codebase Index

Last reviewed: 2026-06-12

Purpose: a compact map for surgical codebase reads. Keep this file current when module ownership, commands, or architecture changes.

## Stack

- Strict TypeScript Vite browser app using native ES modules, a module Web Worker for chunk CPU work, and a shared `WorkerPool` with real Web Worker dispatch plus sync fallback for browser-native CPU job migration. Partial-terrain region meshing is the first WorkerPool runtime job.
- Three.js handles rendering, camera, materials, lights, and meshes.
- Rapier (`@dimforge/rapier3d-compat`) handles active rigid-body cuboid-envelope debris inside the player bubble through the local `src/rigidDebris.ts` adapter.
- Vercel Blob (`@vercel/blob`) stores deployed production hitch logs as private JSONL blobs through the Vercel function in `api/hitch-log.ts`.
- World units are metric: `1 block = 1 meter`, defined by `METERS_PER_BLOCK` in `src/voxelConstants.ts`.
- The app code owns chunks, terrain generation, voxel meshing, partial-block terrain carving, player movement, collision, ray picking, split item/block selection, HUD, minimap, admin/test-lab/builder tooling, impact damage, parked crater/scar visuals, debris VFX lifetime/cleanup, parked rubble cover proxies, projectile physics toys/cores, and hitscan cores.

## Runtime Flow

1. `index.html` loads `src/main.ts`.
2. `main.ts` creates the Three.js renderer, scene, lights, camera-following generated skybox, `VoxelWorld`, `PlayerController`, and small UI helpers for quality, debug HUD, minimap, and world list rendering.
3. `main.ts` opens the async IndexedDB save registry, then starts on the home screen; `worldMenu.ts` renders saved-world rows, and loading, creating, Superflat Lab creation, or confirmed deletion updates the saved-world slots, active seed, and optional player resume location.
4. `VoxelWorld` reads the saved chunk key index when a world loads, but chunk payloads stay lazy and stream from IndexedDB only when needed.
5. `VoxelWorld.ensureChunksAround` creates initial spawn chunks after a world is loaded; generated chunks use seeded `fbm2` terrain noise from `src/terrain.ts`.
6. During play, `main.ts` passes the camera view direction and camera frustum into `VoxelWorld.streamChunksAround`; cached chunk-radius offsets populate the queue only when the player crosses a chunk boundary or the load radius changes, unchanged unload windows skip loaded-chunk sweeps, then chunk generation queues are picked as a bounded slice that keeps nearby chunks first and prioritizes chunks inside the camera view. After streaming and dirty mesh work, `VoxelWorld.updateChunkRenderVisibility` hides loaded chunk meshes that are beyond the opaque fog curtain plus one safety ring while keeping them streamed.
7. Completed worker/storage chunk results are also applied in camera-prioritized bounded slices, so high-distance fresh worlds do not upload large bursts of chunks or let offscreen results steal the visible-frame budget.
8. Dirty chunks are tracked by key, then use the same bounded frustum-biased priority before meshing in the worker as typed-array buffers and uploading through `Chunk.applyMeshData`; worker and fallback meshes both use `src/blockColors.ts` and `src/blockTextureTiles.ts` so deterministic tint buckets, atlas tile attributes, and texture variants do not change between mesh paths.
9. If workers are unavailable or fail, `VoxelWorld` falls back to synchronous chunk generation and `Chunk.rebuildMesh`.
10. Each visible animation frame updates player motion, optional F8 test-avatar scripting, Nova Pilot companion motion/reactions, Nova Terminal runtime context, chunk streaming, physics toys/cores with reusable impact buffers and slider-tuned projectile launch size/velocity/terrain-bounce count, partial-block terrain carving, rubble-core collision for parked cover experiments, damage health-bar projection, Rapier rigid debris and temporary static terrain/rubble colliders, settling-region debris VFX cleanup, adaptive debris pressure, far/budget shard expiration, rubble patch merge/support/fall/terrain-promotion rules when rubble exists, a sleep-aware split core/debris broadphase shove pass, speed-gated impact damage, quality-scaled and slider-tuned physics body budgets, instanced debris render batches, dirty mesh scheduling, regional partial-block mesh refreshes, fog-hidden chunk render visibility, bottom hotbar/control-hint/debug/minimap UI, and final render only while a world is active. Hidden tabs and long resume gaps skip expensive work and reset profiler/minimap meters; once chunk, worker, save, debris, and awake-physics work has drained, visible worlds with no input for five minutes stop RAF entirely and use a low-frequency idle heartbeat until focus, visibility, pointer, or keyboard activity resumes the loop. The debug HUD starts hidden, then receives rolling elapsed-time frame-rate samples, low-FPS samples, smoothed CPU timing buckets for player, chunk, physics, mesh, minimap, render, miscellaneous work, settling-region pressure, rigid debris body/collider pressure, adaptive debris pressure, fragment instancing pressure, partial-block lattice/subvoxel pressure, partial-region dirty/rebuild/max-triangle pressure, loaded/frustum/rendered/fog-hidden chunk pressure, shared worker-pool pressure, and rubble cover pressure when toggled with F3. Browser automation can also drive `globalThis.__VOXEL_CODEX_PILOT__`, which holds/release real player keys, selects hotbar weapons, fires the real primary action path, and starts focused hitch-log passes.
11. `Exit to Home` saves the player feet position plus look angles, flushes async chunk writes, and unloads the active world view; switching worlds happens from the home screen, not the pause menu.
12. The `G` key toggles between the gameplay Items lane and the building Blocks lane, and `T` toggles held click actions between Semi Auto and Full Auto. The bottom hotbar displays the active lane plus the current `SEMI`/`FULL` click cadence, and the scroll wheel/number keys select within that lane: Items contains Unarmed, Terraformer, Physics Core, and Hitscan Core, while Blocks contains the placeable terrain palette. The pause-menu Loadout panel provides card-based Tools and Blocks selection that resumes gameplay after picking. `src/items.ts` owns reusable item definitions and primary/secondary action descriptors, `src/hotbar.ts` owns lane item creation and selection helpers, `src/clickFireMode.ts` owns click-cadence normalization/display helpers, and `src/builderTools.ts` owns centered builder brushes. Unarmed is intentionally inert, Terraformer uses left click to delete the exact highlighted sub-cell brush, selected blocks left-click erase and right-click place the selected block brush, selected Physics Core uses left click to throw, and selected Hitscan Core uses left click to fire an instant smallest/fastest core trace plus a short additive beam flash. Semi Auto performs one action per press; Full Auto repeats held left/right click actions at a bounded cadence through the main input loop. `src/terraformerSettings.ts` owns the clamped `1..4` sub-cell brush setting shared by Settings > Gameplay and ArrowUp/ArrowDown, while `VoxelWorld.raycastTerraformerTarget` retargets exposed partial-block cells and `VoxelWorld.previewTerraformerEdit` grows the brush inward along the targeted face normal so larger sizes carve depth rather than air outside the face. `src/builderPreview.ts` draws a translucent selected-block-color ghost of the right-click placement volume while the Blocks lane is active. The pause-menu Builder panel can switch lanes, tune brush size, run place/erase at the current target, and spawn admin fixtures using the block selected from Loadout > Blocks. Player-fired cores hip-fire from a lowered right-side muzzle that converges through the reticle target; holding right click while firing switches to centered reticle ADS and eases the camera into a slight 15% zoom for core weapons only. The optional F6/Core Aim Preview overlay draws a dotted predicted throw arc for Physics Core, a straight dotted beam for Hitscan Core, first-hit impact rings, and the sparse 3x3x3 bite cells that would be affected by the next terrain impact without mutating terrain.
13. Block edits go through `voxelRaycast` plus `VoxelWorld.setBlock`; edited chunk snapshots are coalesced per chunk before IndexedDB receives raw binary chunk payloads, and neighboring chunks are marked dirty when edge blocks change.
14. Terraformer, projectile cores, and hitscan cores all resolve terrain damage against one material-scaled HP pool. Compact material toughness remains Leaves 3, Sand 5, Grass 6, Dirt 8, Ember 10, Wood 12, Stone 16, and Rubble 4, but runtime full-block HP is old HP times `270`, and one Terraformer sub-cell is old HP times `10`. Terraformer is the deterministic editor path: it raycasts exact remaining partial-block lattice cells, previews exact global `3x3x3` sub-cells under the reticle, skips already-removed cells, and spends exactly the remaining HP for the highlighted brush. Terraformer cuts carry exact removed lattice indexes, so fallback partial-cell reconstruction bypasses the normal neighbor-spreading bite path, and exposed exact-cut walls render as clean cuboid faces instead of wrinkled impact damage on adjacent sub-cells. Projectile and hitscan cores resolve terrain impacts through the same carving path as before: projectile impacts above 2 m/s carry the source core, incoming velocity, and core radius after the swept core moves, while Hitscan Core fires a fixed smallest/fastest trace from the current player firing solution and applies the same impact payload immediately. Both call `VoxelWorld.carveBlockBrush` with `PARTIAL_BLOCK_CORE_DAMAGE` (`270`) against scaled material HP; that brush keeps centered hits to the struck macro block but can promote seam/corner-overlapped neighboring macro blocks into their own sparse 3x3x3 partial lattices. A chipped terrain block stays solid for player/debris collision, normal block placement raycast, and health tracking, but Terraformer targeting, core collision, and thrown-core collision ask the remaining bite-lattice material instead of the old full-cube shell. Normal chunk meshing treats chipped cells as custom geometry through partial-block masks while `PartialBlockMeshField` renders an apple-bite style partial volume from a hidden 3x3x3 visual lattice. Lattice cells are removed either by exact Terraformer selection or in proportion to damage/maxHealth for core impacts, where core cells are ranked by distance from the swept trajectory and then by depth. New bites grow through face-adjacent neighbors, and sparse brush target filtering keeps previewed and carved micro-cells connected in world space, so HP/material loss and visible fill stay coupled without letting later hits visually refill earlier bites, opening isolated seam/corner islands, or making the old 27-piece grid gameplay truth again. `VoxelWorld.carveBlock` reports newly removed bite-cell centers for material-tinted poofs plus debris ejection hints that prefer exposed bite holes and drilled tunnel exits, while `carveBlockBrush` aggregates those per-block results for one impact event. Tiny fast cores can continue through a complete three-depth bite tunnel when their primary impacted cell's exit is air; projectile cores get an exit pose through `PhysicsToy.continueAfterPierce`, while Hitscan Core advances its ray origin and reduced impact speed through the same tunnel continuation. Existing visual tunnels are core-open too: later tiny shots ignore the removed cells and can hit a visible block behind the chipped voxel, while shots through remaining side material still collide with the chipped block. Every carve ejects only the normalized material slice it removed as a slider-scaled chip burst, and material identity controls chip cadence, preferred debris shapes, and ejection feel. Spawned shaped fragments fit the total material budget, a per-piece cap of 70% of one 3x3x3 damage-lattice subvoxel, and a visual-axis cap of 60% of a subvoxel edge. Once accumulated carve damage exhausts block health the voxel is removed, leftover presentation material spawns as proportional loose shaped fragments, and the custom bite mesh is cleared so the final break leaves air instead of a wrinkled surface puddle. Visible fragment count is only a performance/rendering knob after the mass-safe minimum is satisfied: one full block is `1.0` normalized presentation/material volume distributed over its chip and final-fracture events, while durable terrain damage is owned by HP and the partial-block lattice instead of the old debris-to-rubble bake-out. New fractures join nearby temporary settling regions, burst apart for a short breakup grace, then briefly collide/glue/stack/clump with same-region debris, add exaggerated shard tumble through `PhysicsToy.angularVelocity`, and rest on terrain or existing partial-height rubble surfaces. Debris reports whether it touched support during its most recent physics update and whether its sleep state is support-anchored, allowing supported glue-connected clumps to sleep even when upper shards are resting on other debris rather than terrain. Sleep checks run per glue-connected component and then per-fragment support chain so a grounded shard can support stack-like upper debris without freezing side-linked or visibly floating debris. Glue links also maintain a minimum readable center separation so the sticky clump illusion does not preserve obvious fragment interpenetration. In the browser loop those owned regions now stay active or sleeping while inside the quality-scaled player debris bubble; they expire as VFX when the player leaves the radius plus buffer, grounded lifetime finishes, stuck partial-block/tunnel cleanup triggers, physics-budget pressure needs relief, Hitscan Core clears the beam path, or full cleanup clears the world. Budget pressure expires farthest debris regions and orphan fragments before pruning old cores directly. Parked rubble patches can still merge across neighboring same-height cells, skip internal mesh faces, keep bounded surface samples, render faceted low-poly cover, bake static shard samples, expose partial-height support queries, fall when unsupported, and compact into generated `Rubble` terrain when deliberately used by tests or future experiments. Active projectile cores can still shove loose fragments and collide with parked rubble patches without enabling permanent debris-debris pair generation; `PHYSICS_CORE_BLOCK_DAMAGE` (`30`) still applies to directly struck rubble piles, only immediate neighbors get a small non-lethal chip if that pile breaks, and a projectile core is consumed if it destroys the pile cell it struck. `X` removes only thrown cores so rubble experiments can stay in place, while the settings-panel `Despawn All Objects` button clears cores, loose debris, settling regions, rubble, and damage indicators. Projectile cores also sleep after settling so old shots do not keep paying per-frame voxel collision cost forever.
15. `Enter`, `F9`, or the pause-menu `Nova Terminal` button opens the local terminal pane. Normal text feeds replies from the `NovaContextJournal`; slash commands and bare known admin commands route through `src/adminCommands.ts`. Opening the terminal suspends movement/look without showing the pause menu and resumes pointer lock when closed. The conversational implementation is local context-aware text only; a real model/proxy hook is future work.
16. Dev reloads and browser unloads run `disposeRuntime()` from `src/main.ts`: the active animation frame is canceled, main event listeners are aborted, player input listeners are disposed, active chunks/worker/physics/Nova helpers are released, and the renderer forces WebGL context loss so Firefox's GPU process does not keep old dev contexts around.

## Base And Bolt-On Boundaries

Long-term direction: keep this repo as the kitchen-sink proving ground, but shape mature systems so a new game instance can pick a base plus selected bolt-ons without dragging every experiment along. The immediate goal is documentation and small interface boundaries, not a package split.

- Base voxel instance: `index.html`, `src/main.ts`, `src/world.ts`, `src/chunk.ts`, `src/chunkWorker.ts`, `src/chunkProtocol.ts`, `src/terrain.ts`, `src/voxelConstants.ts`, `src/collision.ts`, `src/raycast.ts`, `src/blocks.ts`, `src/blockColors.ts`, `src/blockTextureTiles.ts`, `src/blockTextureAtlas.ts`, `src/voxelLighting.ts`, `src/lighting.ts`, `src/skybox.ts`, and `src/shadows.ts`. This is the hardest piece to extract because chunk storage, meshing, terrain generation, collision queries, and the play loop are intentionally interwoven for now.
- Player-control bolt-on: `src/player.ts`, `src/playerMovement.ts`, `src/playerSpeed.ts`, and `src/sprintFeedback.ts`. Desired extraction contract is a world collision/support query, a camera/input surface, and a movement-tuning object.
- Save/world-menu bolt-on: `src/chunkStorage.ts`, `src/worldMenu.ts`, `src/deleteWorldDialog.ts`, plus the home-screen orchestration in `src/main.ts`. Desired extraction contract is an app identity/storage namespace, seed metadata, edited-chunk payload format, and optional player resume pose.
- Held-item/action bolt-on: `src/items.ts`, `src/hotbar.ts`, `src/clickFireMode.ts`, `src/terraformerSettings.ts`, plus focused action dispatch in `src/main.ts`. This is already close to portable because held-item behavior is mostly data plus a small runtime dispatcher; the current app deliberately separates gameplay tools like Terraformer/cores from build-only block entries so a game instance can carry one lane without the other.
- Builder/admin-tool bolt-on: `src/builderTools.ts`, `src/builderPreview.ts`, fixture commands in `src/adminCommands.ts`, Builder panel markup in `index.html`, styling in `src/style.css`, and block-lane dispatch in `src/main.ts`. Desired extraction contract is a target ray, a world set/get block surface, optional player-overlap rejection, selected-block color, scene ownership for the preview ghost, and named fixture hooks; it should not own normal gameplay weapon behavior.
- Damage/targeting feedback bolt-on: `src/targetHighlighter.ts`, `src/damageIndicators.ts`, `src/combatLog.ts`, terrain/rubble damage events in `src/engineEvents.ts`, and the target-selection hooks in `src/main.ts`. Desired extraction contract is a targetable cell/source id, world-to-screen projection, health-event payload, and structured damage log entry.
- Partial-terrain carving bolt-on: `src/partialBlocks.ts`, carve ownership in `src/world.ts`, partial render masks in `src/chunkProtocol.ts`/`src/chunkWorker.ts`, normal-cube suppression in `src/chunk.ts`, material poofs in `src/debrisPoof.ts`, and `handlePhysicsImpact`/`PartialBlockMeshField` wiring in `src/main.ts`. Chipped terrain remains a full voxel through `VoxelWorld.isSolid`, while its visible custom mesh removes hidden lattice cells in proportion to damage and ranks those cells by core trajectory/radius. `VoxelWorld.carveBlock` is still the single-block primitive; `VoxelWorld.carveBlockBrush` visits only nearby solid macro blocks overlapped by the impact brush so seam hits can create continuous sparse microfracture damage without making the whole world small voxels. Brush fan-out distributes one shared impact damage budget across touched macro blocks by overlap/primary weighting; it should not multiply HP/material loss by target count. Tiny-core piercing is projectile-only and returns an exit pose through the primary carve result; later core projectile collision can also pass through already-removed lattice cells via `VoxelWorld.canProjectileHitBlock`, while thrown Physics Core sweeps use `VoxelWorld.getProjectileBlockSweepHit` to collide against the first visible remaining bite cell instead of the old full-cube envelope. Final fracture clears the bite mesh and leaves air. Save persistence and richer non-cuboid collision are future deliberate steps.
- Impact-scar prototype: `src/impactCraterField.ts` is parked after the decal-like crater experiment. Keep it visual-only if reused later; it should not own terrain damage, rubble material, collision, or the active core impact route.
- Quality/performance bolt-on: `src/qualityPresets.ts`, `src/qualitySettings.ts`, `src/qualityController.ts`, `src/physicsBudget.ts`, `src/physicsCoreSettings.ts`, `src/rigidDebrisBudget.ts`, `src/debrisPerformanceGovernor.ts`, `src/frameTimings.ts`, `src/frameDiagnostics.ts`, `src/workerPool.ts`, `src/performanceHitchLog.ts`, `src/remoteHitchLog.ts`, `api/hitch-log.ts`, the dev-server marker launcher in `scripts/dev-server.mjs`, the standalone local hitch-log receiver in `scripts/hitch-log-server.mjs`, and debug-HUD display in `src/debugHud.ts`. This should stay policy-driven: presets tune budgets/radii/counts, render-horizon visibility hides only fully fogged chunk meshes, and CPU-heavy systems should plug into the shared worker-pool protocol instead of hard-coding their own browser job queues. Partial-block performance snapshots should carry both macro damaged-block counts and remaining/cut 3x3x3 subvoxel totals so terrain-carving pressure is debuggable separately from loose debris. Low-FPS samples should stay rate-limited to one record per second below 60 FPS and share the same stats payload as hard 45ms+ frame hitches, including browser-frame diagnostics when RAF cadence, long tasks, or unaccounted JS frame time point outside measured engine buckets. Render-led summaries should lead with current renderer counters before stale recent long-task context, while low-FPS summaries still prefer current RAF-gap or overlapping-long-task clues. Remote production hitches should keep carrying app version, pass/session ids, browser source, and Vercel deployment metadata so deployed performance reports can be tied back to exact code.
- Physics-core bolt-on: `src/physics.ts`, `src/physicsCoreLaunch.ts`, `src/coreAimPreview.ts`, `src/hitscanCore.ts`, `src/hitscanDebris.ts`, `src/hitscanBoltTracer.ts`, `src/assets/hitscan-energy-bolt.png`, `src/physicsCoreSettings.ts`, plus selected core dispatch and `PhysicsToyCollider` use in `src/main.ts`. Desired extraction contract is scene ownership, collision bounds/support queries, impact callbacks, launch tuning for projectile cores, player muzzle/ADS policy, fixed-envelope trace tuning for hitscan cores, non-blocking loose-debris clearing, optional preview overlays, and optional shot-line VFX. Keep core behavior separable from durable rubble so a new instance can keep projectiles or hitscan weapons without destruction cover.
- Debris-visual bolt-on: `src/blockFragments.ts`, `src/debrisShapes.ts`, `src/debrisCleanup.ts`, `src/debrisPoof.ts`, and `src/physicsInstancing.ts`. This is one of the cleanest reusable pieces: given source material/block id, fragment positions, transforms, shape metadata, optional stuck-cleanup policy, and optional short-lived poof cues, it can render many transient fragments through shared geometries and instanced batches.
- Rigid-debris bolt-on: `src/rigidDebris.ts` plus budget policy in `src/rigidDebrisBudget.ts` and the adaptive low-FPS governor in `src/debrisPerformanceGovernor.ts`. This is intentionally adapter-shaped: Rapier stays behind local methods, dynamic bodies use cheap cuboid envelopes, and terrain/rubble/partial-lattice support enters through candidate-filtered capped surface-only path-lookahead static-collider refresh inputs plus stale partial-support wakeups and shallow support-penetration correction before fragment transforms sync back to rendering. The partial-lattice support path should receive merged exact cuboids from `src/partialBlocks.ts` rather than one collider per surviving sub-voxel, because high-damage playtests can otherwise turn the surface layer itself into the physics bottleneck. Low-motion shards are aggressively slept in Rapier while they stay inside the active debris bubble, then wake from core-side `PhysicsToy` mutations, partial-block support changes, or active debris contact until lifetime, distance, or budget cleanup expires them as VFX. Extreme airborne bursts can expire farthest active shards once they exceed the effective rigid-body cap instead of waiting for every shard to touch ground, the grounded-debris cap trims only supported/sleeping aftermath clutter after the short burst-grace window, and sustained sub-60 FPS can temporarily lower the effective rigid-body cap until frames recover.
- Rubble/cover bolt-on: `src/rubble.ts`, parked rubble finalization paths in `src/debrisSettler.ts`, and legacy eligibility in `src/fragmentRubble.ts`. This is powerful but currently parked because partial-block terrain damage owns durable gameplay while loose debris is VFX. If revived, split the durable cover proxy from voxel-world promotion policy instead of re-coupling it to normal debris cleanup.
- Event/reaction bolt-on: `src/eventBus.ts`, `src/engineEvents.ts`, `src/novaPilotReactions.ts`, `src/novaContext.ts`, `src/novaChat.ts`, `src/novaChatPanel.ts`, and `src/novaPilot.ts`. Keep engine events generic enough that Nova can be removed, replaced, or kept as a flavor layer without rewriting damage, world, or physics systems.

When adding a new mature feature, add it to this list with three things: owning files, external contracts it should depend on, and the parts it should not directly own. Prefer small TypeScript interfaces at module boundaries once a second instance actually needs the system; until then, avoid premature package structure and keep the kitchen sink pleasant to work in.

## Sharp Edges

- Prefer `rg` for repo search. If Windows ever resolves to the protected Codex-bundled copy under `C:\Program Files\WindowsApps`, use the working user-local copy at `C:\Users\apoli\AppData\Local\OpenAI\Codex\bin\rg.exe` or `C:\Users\apoli\codex\tools\ripgrep\rg.exe`.
- `.env.local` and `.vercel/` are local Vercel/Blob linkage artifacts and must stay untracked. The Blob token lets the CLI inspect private production hitches; do not echo it in chat or commit it.
- Vercel serverless functions run as Node ESM after deployment; imports from `api/` into shared TypeScript modules need Node-resolvable `.js` specifiers even when the source file is `.ts`.
- `VoxelWorld.savedChunkKeys` mirrors the persisted edited chunk index; `savedChunks` is only a cache of loaded edited chunk payloads.
- Saved worlds are local browser slots in IndexedDB; edited chunks persist as full binary chunk snapshots, which is simple and reliable but not a final save-file format. Because edited chunks are full snapshots, saved-world terrain-profile metadata must travel with the seed so old chunks do not border newly streamed chunks from a different generator profile.
- Player resume location is saved as feet position plus yaw/pitch in saved-world metadata; avoid storing raw camera height or crouch view offsets, or crouched exits can reload into terrain.
- Edited chunk saves are debounced and coalesced per chunk so rapid destruction does not spam IndexedDB with intermediate snapshots; call `VoxelWorld.flushStorageWrites()` before switching storage or unloading a world.
- Worker meshing has a synchronous fallback path; keep both paths healthy when changing chunk storage or mesh formats. New CPU-heavy browser jobs should use `src/workerPool.ts` for ids, revision rejection, cancellation, transfer accounting, telemetry, and fallback semantics.
- Block tint variation is part of the greedy mesh key. Keep worker and fallback meshing on the shared `src/blockColors.ts` helpers so tint buckets stay deterministic and chunks do not repaint between mesh paths.
- Worker meshes treat missing neighbor chunks as temporarily solid so streaming does not draw chunk-edge walls before neighbors load and trigger a remesh.
- Chunk `revision` values invalidate worker mesh results for both local block edits and neighbor-driven dirty marks; do not let stale neighbor snapshots clear `dirty`.
- Large render-distance presets depend on bounded frustum-biased chunk and mesh selection in `src/world.ts`; avoid reintroducing full queue sorts, full chunk-radius queue refreshes, full unload sweeps, or all-loaded-chunk dirty scans on every frame. The settings slider is the fog-start/clear-distance radius; `QualityController.streamLoadRadius` is the farther hidden horizon that keeps the hard chunk cutoff behind fully opaque fog, while `QualityController.chunkRenderRadius` is the nearer draw radius that hides only fully fogged loaded meshes plus one safety ring. Do not collapse `fogFar` back onto `streamLoadRadius`, or distant chunks become a visible square fog wall again; do not expand `chunkRenderRadius` back to the full stream radius, or hidden-horizon draw pressure returns. If code clears pending load state or makes a saved chunk fall back to generated terrain, call the queue-window invalidation path so unchanged-center streaming can safely repopulate missing work. If code loads or creates chunks directly, keep the unload-window and dirty/modified indexes in sync.
- `Super Ultra` is intentionally gated by a pause-menu opt-in that only appears at `Ultra` or while `Super Ultra` is active.
- Pause-menu tuning controls live behind the `Settings` button and admin build controls live behind the `Builder` button so normal pause/resume stays quick; opening a submenu hides `Resume` and the red `Exit to Home` action until the user backs out. The settings panel is viewport-constrained and split into `Graphics`, `Gameplay`, and `Experimental` tabs to keep smaller windows reachable while putting risky physics/debris stress controls behind a warning.
- Slider edits intentionally fork into the single `Custom` preset instead of mutating built-in presets; named custom preset management is future UI work.
- Browser worker behavior can differ from the build smoke test; reload the local app after worker pipeline changes and watch console logs/debug metrics.
- Firefox can retain WebGL/GPU-process memory across dev reloads if old contexts are not explicitly lost. Keep `disposeRuntime()` wired to `beforeunload` and Vite HMR, and keep long-lived Three.js helpers on a disposal path when adding new renderer-owned resources.
- Long idle sessions should hibernate instead of trusting browser RAF throttling. Keep `src/frameLoop.ts` and `VoxelWorld.hasPendingRuntimeWork()` in sync when adding new async queues or persistent simulation work, or the engine may sleep too early or run overnight again.
- `npm.cmd run test` bundles `tests/run.ts` into `.test-dist/` with esbuild before running in Node; `.test-dist/` is generated and ignored.
- `node_modules` and `dist` are generated and should not be scanned unless diagnosing dependency/build output.
- `vite.config.ts` manually separates Three.js into a `vendor-three` chunk and keeps other dependencies in `vendor`, so production build warnings point at genuinely oversized app code instead of the stable renderer dependency.
- Object-object physics is split: Rapier owns active debris-debris cuboid contacts, while `PhysicsToyCollider` keeps the cheap core/core and core/debris shove pass in spatial hashes. Call both `PhysicsToyCollider.forget()` and `RigidDebrisSimulation.forget()` before disposing a toy so sleeping/static caches and Rapier bodies cannot keep stale references.
- Physics-core size, velocity, and terrain-bounce sliders affect newly thrown player and Nova projectile cores only. Hitscan Core always uses the smallest core radius and highest configured impact speed. Projectile cores spend one terrain bounce only when a terrain impact actually applies damage; the default one-bounce setting preserves the old hit-once self-destruct behavior, while higher values let a core ricochet and dig repeatedly. Surviving terrain-damaging rebounds bleed velocity after the collision response, so high bounce counts still lose momentum as they carve. Thrown Physics Cores also have a 20 second hard TTL plus a short fade/despawn countdown once they stay below useful terrain-damage speed, preventing spent shots from accumulating forever in physics stress tests. Core-vs-terrain contact uses a swept sphere path or hitscan trace so tiny fast cores hit the first remaining bite-lattice material along the segment; intentional piercing must happen only through the primary result of `VoxelWorld.carveBlock`/`VoxelWorld.carveBlockBrush` after the bite lattice opens a complete tunnel and confirms an air exit.
- Core Aim Preview is debug assistance, not gameplay truth. It should stay selected-core-weapon-only, use the same launch helpers and projectile/hitscan trace hooks as the real cores, call `VoxelWorld.previewBlockDamageBrush` for non-mutating lattice cells, classify predicted bite cells against the current camera position, and hide/dispose both bright visible and soft red hidden-cell Three.js resources cleanly when disabled or leaving the world.
- Debris fragments are rendered through per-block/per-shape `THREE.InstancedMesh` batches in `src/physicsInstancing.ts`; Rapier writes active fragment transforms back into `PhysicsToy.mesh.position` and `mesh.quaternion`, while `debrisShape.visualScale` stays render-side and fragment meshes are not added to the scene individually.
- Partial-block terrain carving is in-memory first-pass terrain state. `VoxelWorld.carveBlock` keeps chipped cells solid for player/debris collision and raycast through `isSolid`, but `isRenderableSolid` makes chunk meshing skip those cube cells while `PartialBlockMeshField` draws the custom faceted bite volume. Partial visuals are indexed into 4m x 8m x 4m regions with a one-block halo for face visibility and surface stitching; urgent topology changes rebuild first, while repeated cuts stay on the regional soft-budget lane instead of re-uploading the whole damaged field. Partial geometry must emit both `uv` and `blockTextureTile` attributes and use an atlas-backed block material, matching chunk meshes so damaged materials do not fall back to flat colors. Chunk worker masks are cached sparsely by chunk, and repeated damage to an already-partial cell dirties only the custom visual region unless the cell enters/leaves partial state or touches a chunk-edge visibility boundary. `VoxelWorld.carveBlockBrush` is the runtime impact entry point for cores: it fans one hit out to only the nearby macro blocks overlapped by the sparse brush, distributes the one hit's damage/material budget across those targets, then each target still uses the same per-block HP/material/lattice primitive. Thrown cores use `getProjectileBlockSweepHit` for first-hit timing against the remaining bite cells, while boolean projectile checks still use `canProjectileHitBlock` so cores can pass through removed lattice cells without skipping visible partial material. Each carve result reports the normalized rubble-material volume it just ejected so `src/main.ts` can spawn chip debris without duplicating the final block budget, and the primary result may report a projectile-only pierce continuation when a small fast core opens a complete bite-lattice tunnel into air. Removed bite-lattice cells are stored on the partial block and only expand as damage increases, preventing later hits from visually refilling older bite marks when the rolling cut list changes. Bite ranking uses the incoming core line and radius, but selection grows through face-adjacent frontier cells so removed sub-voxels stay connected with no isolated holes; tiny-core pierce tunnels lock to one lateral column through the dominant travel axis only when enough material budget exists for a full tunnel. Secondary sparse-brush targets carve inward from their touched face, and brush targets whose preview/carve cells do not connect back to the primary footprint are filtered out and reweighted so seam/corner fan-out does not create disjoint islands. When a carved voxel breaks, `VoxelWorld` clears the custom bite mesh and leaves normal air instead of stamping the old wrinkled heightfield support puddle. Partial render masks must travel with worker mesh requests or the worker will resurrect full cubes over carved cells. Partial cells are not saved to IndexedDB yet; leaving the active world clears them.
- Parked warning: do not revive the reverted v0.9.7 partial-mesh draw-cap path as the next serious optimization. It hid far/off-budget damaged-region meshes, but the visual result was worse and the logs showed the stress case had moved to projectile/physics work instead of partial draw pressure. Partial blocks are also likely to become persistent terrain state, so the better future path is to optimize the persistence/data model and physics interaction rather than masking partial visuals at render time.
- Parked warning: do not revive the reverted v0.10.2-v0.10.4 rigid-debris cadence throttle as a quick debris optimization. Lowering/skipping active debris solve cadence made fragments feel wrong even with interpolation and fixed-step tweaks; future debris performance should start with body count, sleeping/islands, broadphase/support-collider cost, or gameplay rules instead.
- `ImpactCraterField` is now a parked visual-only prototype from the rejected decal-like crater pass. It should not be wired back into Physics Core terrain hits unless the feature is deliberately a surface scar again, and it must not become terrain collision, rubble material, or save data by accident.
- `Despawn All Objects` uses the full cleanup path and releases high-water instanced debris batches, while `X` removes only thrown physics cores and preserves fragment/rubble experiments.
- Loose debris is VFX in the normal runtime. `RigidDebrisSimulation` owns active cuboid contacts inside the bubble, while `DebrisSettler` owns temporary region grouping, wakeable sleep/clump bookkeeping, and VFX-mode cleanup when debris gets far away or budget pressure needs relief. Sleeping rigid-body regions remain wakeable inside the active player bubble, but the ground-debris cap culls only excess supported/sleeping visual clutter after impact and after the short burst-grace window; do not wire it back into initial burst count, nominal active-body budget, or first-frame support contact. The rigid-body cap can cull farthest active shards during extreme airborne bursts, and the adaptive pressure governor can temporarily lower that cap during sustained sub-60 FPS; the lifetime slider can timer-expire shards after first ground contact without countdown flashing. Stale never-grounded floaters and trapped partial-block/tunnel clutter fall back into forced poof cleanup after a grace window, and Hitscan Core can clear loose shards along its beam without blocking terrain drilling. `RubbleField` is still parked as a useful cover experiment with hidden support footprints, baked shard visual chunks, cover raycasts, scaled health, core collision, walkable partial-height support queries, fall/merge behavior, and promotion into the generated `Rubble` block; the old faceted/draped heightfield renderer is parked behind `RUBBLE_RENDER_DRAPED_SHEET_MESH` and should stay disabled unless that zoomed-out rubble mechanic returns deliberately. Do not reintroduce automatic debris-to-rubble bake-out unless the mechanic is deliberately revived.
- The player and loose debris receive terrain collision and rubble support through the shared `CollisionWorld` contract in `src/collision.ts`; full voxel blocking still comes from `isSolid`, while partial-height surfaces should opt in through `getSupportHeight`.
- Engine/gameplay events are local typed pub/sub, not DOM events; keep cross-system reactions on `src/eventBus.ts`/`src/engineEvents.ts` instead of stringly `CustomEvent` wiring.
- Item actions are data contracts. Add future tools, weapons, consumables, or game-mode commands by extending `ItemAction`/`ItemDefinition` in `src/items.ts`, then dispatch the new action in `src/main.ts` or a focused gameplay owner; avoid reintroducing direct hotbar-kind checks.
- Nova Terminal chat is deliberately local-only for now. Do not put OpenAI/API credentials in browser code; use a tiny local/backend proxy when the real model hook happens.
- Pointer lock behavior is browser-sensitive; `requestPointerLock()` can return a promise or `void`, so keep the guarded catch path in `src/player.ts` and test movement changes in the browser, not just with `npm.cmd run build`.
- TypeScript migration helpers are historical prep tools now; source in `src` is expected to stay strict without `@ts-nocheck` or explicit `any`.
